Reports filed (buildable class, HYB-E1002 / GUARANTEES row 13)

#4223 · associated functions skip member & argument resolution

accepted → unbuildable

fn box.new(v int) box lowers to box_new, and the selector base skips the member check that every other callee gets. b.new(2) passes hyb check; Go says b.new undefined. The argument-type check is skipped for the same callee: box.new("s") passes and Go rejects the string.

Controls: ordinary fn / method / task / defer with the same mistakes are all rejected on the same commit — only the mangled associated function fails open.

#4222 · package-level redeclaration blind spot

accepted → unbuildable

Two .hy files, or a .hy beside a hand-written .go, that declare the same top-level name: each file passes hyb check alone, hyb generate writes both, and go build fails with redeclared in this block. The headline workflow is “drop a .hy beside your .go files”.

The generator already reads the directory and refuses to overwrite hand-written files, so the package context exists at generate time.

Method

Checker built from source (cargo build --release, pinned rust). Every program goes through hyb check (verdict), hyb generate (transpile) and hyb build --race (cgo race-detector build) — the same pipeline the project's own differential loop uses. Findings are kept only when the program is accepted with 0 diagnostics and the evidence reproduces deterministically; a silent race detector means the candidate is discarded. Duplicate checks are run against the public issue board before anything is filed, and the calibration map above lists what was not reported for exactly that reason.
